# Cues (the prompter): App/Cues

Cues listens to the host's microphone during a live meeting, turns finished sentences into "mentions" (a book, tool, person, word to define, quote...), looks each one up on public sources, and shows a small link card the host can Open (in the main-pane browser) or Send (to the meeting chat). It is on-device speech plus word patterns by default, with an opt-in Apple Intelligence detector and an opt-in whisper transcriber. Everything is macOS 26 only (Speech framework, Foundation Models); below that the coordinator hooks are no-ops. User-facing name is "Cues"; the code and UserDefaults keys still say "prompter" in places (`prompterEnabled`, `prompter_card` analytics).

Context docs: `docs/cues-search-improvement-plan.md` (phased plan: Phase 1 detector bench, Phase 2 resolver bench, Phase 3 model as secondary source; speed/accuracy targets). Real-class evidence behind the 90%/56% (patterns) vs 100%/3% (model) numbers lives OUTSIDE the repo (`~/CuesBench-evidence`), by design.

## How it fits

Start. `CoordinatorController.startCuesIfEnabled()` (called once the meeting is live) checks, in order: `CuesAvailability.isReleased`, `cuesEnabled` (UserDefaults `prompterEnabled`, default off), macOS 26. It builds `CuesController.Configuration` in `cuesConfiguration()` from coordinator settings (`cuesLocaleIdentifier`, `cuesVideoSearch`, `cuesUseModel`, `cuesUseWhisper && CuesWhisperTranscriber.isAvailable`, `cuesSaveTranscript` -> `<sessionFolder>/transcript.txt` and `cues.txt`, YouTube token closure when connected, roster closure from `zoomChatClient`, `log` -> `coordinator.log`). Then `engine.start(configuration:)`, and a 1 s `cuesTickTask` calls `syncCuesSurfaces()`.

Audio to text. `CuesController.startPipeline` picks a transcriber: `CuesWhisperTranscriber` (when `useWhisper` and microphone input) else `Transcriber`. Both read a `MicStream` and yield the same `Transcriber.Event` stream, so nothing downstream knows which ran (whisper windows pass through `CuesStabiliser` first). `handle(_:)` consumes events on the main actor: `.volatile` -> `RollingTranscript.setVolatile` and `liveTail`; `.final` -> `RollingTranscript.appendFinal`, transcript file append, then `runDetection()`; `.speech` -> `isSpeaking`; `.failed` -> whisper falls back to Apple for the session, otherwise one restart then `stopQuietly()`; `.finished` (file input only) -> forced detection then `stop()`.

Detection. `runDetection` takes `transcript.unprocessedText(leadInWords: 20)` (marks them processed), records self-introduced names (`HeuristicDetector.selfIntroducedNames`, never looked up this session), and runs `detector.detect(newText:context:excludedNames:)` on `detectTask` (one at a time). Detector comes from `chooseDetector()`: `HeuristicDetector` by default; `CompositeDetector(model:)` (patterns first, model only for sentences the patterns left silent) when `useModelDetector` and `FoundationModelsDetector.isAvailable`. Cheap detectors run on every final sentence; a non-cheap one waits for `detectMinWords` (6) new words and 2 s. `tick()` (1 s) is the catch-up (every 3 s cheap, `detectEvery` 8 s model). Three consecutive model errors swap the session to `HeuristicDetector`.

Resolution. `detect` returns `[Mention]`; the controller launches `resolve(_:)` on a separate task (so `detectTask` is not blocked by lookups). Per mention: skip if dismissed, `vocabulary.repair` (mishearing fix), skip if it equals a roster/spoken name, skip if a card of same key and kind exists, then `LinkResolver.resolve` (actor): session cap 30, per-minute brake (controller passes 12; `heldBack` mentions are retried by `tick` for up to 120 s, max 10), max 2 in flight, per-kind routing:
- book -> Google Books + Open Library
- video -> YouTube API (token) else a search-link card (`searchLinkOnly`)
- topic/person/place -> Wikipedia (`encyclopediaEntry`)
- thing -> product-site/Wikipedia race (`resolveThing`, `thingFromWikipedia`)
- quote -> Wikiquote
- word -> macOS dictionary, nothing leaves the Mac (`resolveWord`)

Only the first card of a resolution is inserted (`insert`), newest first; `keepCards` 12, `cardLifetime` 1800 s, rotation every 8 s when more than 3 cards. Thumbnails load afterwards through `ThumbnailLoader` and patch the card in place.

Out. `syncCuesSurfaces` (1 s): sets mute-driven pause (`engine.setPaused(isJoined && iAmMuted)`), builds `CuesSurfaceState` (cards via `surfaceCards`, `canSend`, open/send/dismiss closures), pushes it to `ParticipantGridWindowController.applyCues(_:)` -> `CuesRailBlock` -> `CueCardView` when the participants panel is open, else shows `CuesMenuBar`. Never both. Open = `openCueCard` (background tab in Greenroom Browser, or other browser without activating); Send = `sendCueCard` (word cards send "title: subtitle", others the URL, via the chat bridge).

Models and notifications. Models: Apple `SpeechTranscriber` (locale model via `ModelAssets`), optional whisper binary + model (resolved through `ScreenroomWhisper.resolvedBinary` / `ScreenroomTranscriberSettings.resolvedModel()`), optional `SystemLanguageModel` (Foundation Models). There are no `NotificationCenter` notifications in this folder; communication is `@Published` properties on `CuesController` and `CoordinatorController` (`cuesListening`, `cuesPaused`, `cuesLinkCount`, `cuesOnRail`), the 1 s sync tick, and `Configuration.log`. Analytics via `Analytics.feature("prompter_*")`.

## To change X, go to Y

- Add or tune a spoken cue ("it's called X", "a book named X"): `HeuristicDetector.baseTells` / `categoryTells` / `discourseTells` in `MentionDetector.swift`, then add fixtures and run `scripts/cues-bench.sh`.
- Stop a generic word or phrase becoming a card: `HeuristicDetector.genericWords`, `worthLookingUp`, `namesAThing`, `acceptable`, `trimToTitle` (all in `MentionDetector.swift`).
- Change what counts as a name/person to never look up: `HeuristicDetector.isPersonalName`, `selfIntroducedNames`, `filter`; controller second line of defence in `CuesController.resolve`.
- Change dictionary-word or quote triggers: `asksAboutTheWord`, `hasRecitationCue`, `acceptableQuote`; resolution in `LinkResolver.resolveWord` / `resolveQuote`.
- Add a mention kind: `Mention.Kind` + `eyebrow` (`CueCard.swift`), `LinkResolver.resolve` switch, symbol switch in `CueCardView`, `FoundationModelsDetector` instructions/`GeneratedMention.kind`, and any `Source` case + `label`/`analyticsCode` (+ `caps` in `LinkResolver`).
- Add or change a lookup source or ordering: `LinkResolver` (`resolveBook`, `googleBooks`, `openLibrary`, `resolveVideo`, `resolveThing`, `resolveWikipedia`/`encyclopediaEntry`, `caps`, `allowed(_:host:)`); title acceptance in `TitleMatch` and `LinkResolver.titleMatches`/`closestFirst`.
- Change rate limits: resolver `Configuration.sessionCap`/`lookupsPerMinute` (class value is `CuesController.Configuration.lookupsPerMinute` = 12, passed to `resolver.configure` in `start`; resolver's own default is 6).
- Change when detection runs or how much text it sees: `CuesController.handle` (`.final` branch), `tick`, `runDetection`, `detectMinWords`, `detectEvery`; window size in `RollingTranscript` (`window`, `leadInWords`).
- Change which detector is default or how composite works: `CuesController.chooseDetector`, `CompositeDetector.detect`; model prompt in `FoundationModelsDetector.instructions` (no concrete examples, see its comment).
- Change card count, lifetime, rotation: `keepCards`, `cardLifetime`, `rotateEvery`, `tick` in `CuesController`; rail slots `CuesRailBlock.maxCards`/`minCards`.
- Change card look or buttons: `CueCardView` (64 pt height, glyphs). Rail layout and height budget: `CuesRailBlock.height/place/cardsFitting`; panel integration in `App/UI/ParticipantGridWindow.swift` (`cuesBlock`, `applyCues`).
- Change menu-bar fallback: `CuesMenuBar`.
- Change what Open/Send do: `CoordinatorController+Cues.swift` `openCueCard` / `sendCueCard`.
- Change mute/pause or when Cues starts and stops: `startCuesIfEnabled`, `stopCues`, `stopCuesForClass`, `syncCuesSurfaces`; callers in `App/CoordinatorController.swift` (end session / quit call `stopCues()`).
- Change speech recognition: `Transcriber.swift` (Apple); locale/model download UI `ModelAssets.swift`; whisper window/step `CuesWhisperTranscriber.windowMs/stepMs`, agreement rules `CuesStabiliser.forceAfterMs/edgeMs`.
- Fix a mishearing of a repeated name: `CuesVocabulary.repair` / `skeleton`; learning rule in `CuesController.resolve` (`vocabulary.learn`).
- Add a setting: `@Published cues*` in `App/CoordinatorController.swift` (~line 957), `cuesConfiguration()`, `CuesController.Configuration`, UI in `App/UI/CuesSettingsTab.swift`; also check `importSettings` gating on `CuesAvailability`.
- Hide or re-enable Cues for a release: `CuesAvailability.isReleased`.
- Add a resolver test without network: a `RecordedTransport` case in `Bench/Resolver.swift` (`resolverCases()`); timing/concurrency claims use `DelayedTransport`.

## Gotchas

- Opt-in model. `FoundationModelsDetector` is off by default (`cuesUseModel` / `prompterUseModel`). Measured on a real 45 min class: 100% recall but 264 lookups at 3% precision, versus word patterns 16 lookups, 90% recall, 56% precision. Do not make it the default or loosen the patterns without re-running the bench.
- `isCheap` drives scheduling. Regex detector runs per final sentence; the model detector is rationed by word count and a 2 s gap. A new `MentionDetector` must set it honestly. Only one detection pass runs at a time (`detectTask`); `force: true` is the only bypass.
- `unprocessedText` consumes. Calling it marks sentences processed, so two detectors cannot both read the same transcript; this is why `CompositeDetector` chains them rather than running in parallel.
- Threading. `CuesController` is `@MainActor`; `LinkResolver` and `ThumbnailLoader` are actors; the controller awaits them. `RecordedTransport.Log` is `@unchecked Sendable` with a lock. Lookups are launched on their own `Task` so a slow book lookup never delays the next detector pass.
- macOS 26 gate. Everything in `App/Cues` except `CoordinatorController+Cues.swift`, `CuesAvailability.swift` and the AppKit views is `@available(macOS 26)`; the coordinator stores the engine as `AnyObject` (`cuesEngine`) to stay compilable on 14. Keep every touch of the engine inside `if #available(macOS 26.0, *)`. `CuesWhisperTranscriber` is gated only because `MicStream` emits `AnalyzerInput`.
- Release gate has four doors, not one. `prompterEnabled` may already be true in defaults and imported settings can carry it, so all doors read `CuesAvailability.isReleased` (Settings tab, Onboarding step 6, `startCuesIfEnabled`, `importSettings`). Do not gate on the preference alone.
- Privacy promises in code. Only finalised sentences are detected on; the rolling window is memory-only and released in `stop()`; transcript is written to disk only when `cuesSaveTranscript` is on (`transcript.txt`, plus `cues.txt` for links offered); every outbound query is logged before the card exists; dictionary words never leave the Mac; roster and self-introduced names are never queried. Real-class transcripts must stay out of the repo.
- Whisper fallback. A `.failed` event with `CuesWhisperTranscriber.failurePrefix` switches the session to Apple permanently; other failures get one restart (`restartAttempted`), then Cues stops for the session. "no microphone input" stops immediately.
- Debug-only code. `DetectorChoice`, `Configuration.detectorChoice`, `debugSpeak/debugSay/debugInjectSampleCards`, and `CuesWorkbench` are behind `#if DEBUG` (check the release binary with `strings` before shipping). Trace (`note(_:_:)`) records only while a workbench watches.
- Card counts. The code keeps `keepCards = 12`, `cardLifetime = 1800`, and shows up to `CuesRailBlock.maxCards` = 5 (min 3). `LinkResolver.Configuration.lookupsPerMinute` defaults to 6 but the app passes `CuesController.Configuration.lookupsPerMinute` (12) in `resolver.configure(...)` at `CuesController.start`/`startTest`/`debugFeed`.
- Bench is not an XCTest bundle. `project.yml` target `CuesBench` (type tool) compiles real sources: `MentionDetector.swift`, `CuesVocabulary.swift`, `CueCard.swift`, `LinkResolver.swift`, `CuesTransport.swift`, `TitleMatch.swift`, `ThumbnailLoader.swift`, plus `App/UI/ParticipantConsole/ParticipantConsoleState.swift` and `LiveQueueLayout.swift`. Anything those files import from the rest of the app (ZoomSDK, Sparkle, Apptics, `Analytics`, coordinator types) breaks the bench build, so keep them Foundation/NaturalLanguage/AppKit-only. Adding a new file they depend on means adding it to that source list.
- Bench exit status. `Bench/main.swift` exits 0 only if overall detector precision >= 0.70 and the resolver, console, composite, status and rules benches all pass. Run `scripts/cues-bench.sh [--verbose]` before and after any detector or filter change and put both numbers in the commit message. Fixtures are sanitised; the `must-not-fire` cases (35 of 75) exist because a past "long dictionary word" rule shipped unmeasured and produced a card for "happening". Matching is containment either way, not equality (`answers(_:_:)` in `Bench/main.swift`).
- Test coverage elsewhere. `Tests/` has no Cues-specific XCTest file. `Tests/MenuBarModelTests.swift` pins only that `.stopCues` appears when `cuesListening` is true (`testCuesAndUploadAppearOnlyWhenActive`). Layout tests (`LayoutGeometryTests`, etc.) do not cover `CuesRailBlock`; rail fit is verified by arithmetic in `CuesRailBlock.stackHeight` / `cardsFitting`.
- Rail width must not depend on Cues content. A link arriving once changed the rail's width and moved the panel; `ParticipantGridWindow` comments describe the fix. Keep `CuesRailBlock` sizing height-only.
- The session cap and brake count lookups, not cards. Repeats within a session (`resolvedKeys`, `cache`) return `skipped`; a query that found nothing is still counted as resolved and not retried.
- UI words. User-facing strings say "meeting"/"everyone", not "class" (project preference), although log lines and comments in this folder still say "class".
