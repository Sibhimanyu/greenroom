# App/Stage

The in-process "class picture" pipeline (it replaced OBS in 1.3.0). `StageCompositor` captures the shared screen (ScreenCaptureKit via `StageScreenSource`), opens every chosen camera at once (AVFoundation via `CutoutPublisher`, with Vision person segmentation for Cutout, Presenter, Blur and Image backgrounds), draws them with `StageRenderer` (Core Image) at a fixed 30 fps clock into 1920x1080 BGRA IOSurface buffers, and hands each frame to whoever subscribed as a `StageFrameSink`: the meeting (`ZoomVideoSender`), the recorder (`SessionRecorder`), the Settings preview (`StagePreviewSink`) and the Start gate (`StageFrameProbe`). Around it sit `CameraDirector` (auto-cut to the camera that sees the teacher's face head-on), `CameraProbe` (aim a camera before any class runs), the share-target model (`ShareTarget` and the pure rules that pick windows and follow slide shows), and the pure geometry/visibility rules for the on-screen presence bubble. Most files are deliberately pure (no AppKit/SCK) so tests can pin them.

## How it fits

**Camera and share source.** `stageLayout` and `shareTarget` read the coordinator's `meetingSetup` (the active layout's saved camera piece and share, or a for-this-meeting change); there is no working copy any more. The setup tells the Stage when a value in use changes (`applySetupEffect`). With no layout active the old global defaults stand. See layout.md and app-core.md.

**Owner.** `CoordinatorController` holds `var stage: StageCompositor?` (made by `ensureStage()`), plus `let cameraDirector = CameraDirector()`, `let cameraProbe = CameraProbe()`, `let preview = ShapePreviewController()` (owns the `StagePreviewSink`, viewers, feed). Its `runPipeline()` -> `buildScene()` builds a `StageConfiguration` from user settings (shape, `ShareTarget`, the capture display = `effectiveCaptureDisplayUUID`: `screenCaptureDisplayUUID`, overridden for a Whole screen share by the layout's "Everyone sees" display while its two-display version runs (see layout.md), cameras in cut order, background, system-audio flag), calls `stage.start`, then `zoomChatClient.useStageVideo(stage)`; later changes call `stage.update(config)`. Start waits on a `StageFrameProbe` sink (CoordinatorController ~5172) so the meeting never starts on no picture.

**Data flow (per tick).**
1. Inputs arrive on their own queues and drop their newest item into `StageInputBoard` (an NSLock around latest-of-each): `StageScreenSource` (queue `greenroom.stage.screen`) -> `board.offerScreen`; each `CutoutPublisher` (own capture queue) -> `board.setCamera(uid, Frame)`; whiteboard page / marks overlay via `LockedBox`.
2. `StageCompositor.tick()` runs on `renderQueue` (`greenroom.stage.render`, userInteractive, one `DispatchSourceTimer` at `1/frameRate`). It snapshots the board, builds a `StageScene` (layout, liveSlot, crossfade), calls `StageRenderer.compose(scene:screen:marks:cameras:)`, renders into a `StageBufferPool` buffer, and `sinks.deliver(frame, at: hostClockTime)`.
3. Sinks (`addSink`; `addCameralessSink` takes the same picture without the owner's camera, a second compose + render only while one is attached and a camera is drawn, R47): `RoomFrameFeeder` (the Room screen, App/Layout; zero-copy as a CALayer's IOSurface contents, App/Layout/RoomFrameFeeder.swift), `ZoomVideoSender.stageDidRender` (see codemap/zoom.md), `SessionRecorder` (App/Recording), `StagePreviewSink` (downscaled at `PreviewRate`, also feeds Home previews via `ShapePreviewFeed`), `StageFrameProbe`. Sinks are held weakly by `StageSinkList`; whoever creates a sink keeps it alive. A sink must not block: retain, hop to own queue, drop frames.
4. Status for the UI goes through `StageStatus` (@Published), pushed with `post { }` on the main thread, throttled (`pushStatus`).

**Screen sync.** `apply(config)` -> `syncScreen(cfg, generation:)` creates a `StageScreenSource` beside the current one; `board.expectScreen(id)` marks it pending; only its first frame promotes it (`offerScreen` returns true) and then `retireScreens` stops the old one. `screenGeneration` guards stale rounds. Failures go through `ScreenRecovery` (5 s retry while the choice stands, immediately on wake/unlock via `kickScreen`, never for a permission refusal). `DisplayMonitor` events reach it through `CoordinatorController` (~4413) -> `displaysDidChange(connected:main:displaySetChanged:)`; `DisplayPlan` (App/Layout) decides fallback. The display filter (`StageScreenSource.displayFilter`) excludes Greenroom's own app except windows in `ShareVisibleWindows.effectiveNumbers`, and every other app whose 📡 is off (`Visibility.hiddenAppIDs`, by bundle id via `excludingApplications`, so windows it opens later are out too, in recordings and on the Room screen); `ShareVisibleWindows.filterState` (numbers, hidden app ids, their pids so a launch or quit counts) is re-read every second and the filter updated only when it changed; window targets follow a slide show once a second via `SlideShowFollow.decide` when `ShareTarget.followsSlideShow`.

**Cameras and cutting.** `syncCameras` opens every UID in `cameraUIDs` at once (slot = index) and leaves open ones alone. Only `scene.liveSlot` is drawn; hidden ones keep delivering. `CameraDirector` (@MainActor) runs a watch task over `stage.latestCameraFrame(slot:)`, scores yaw/pitch with Vision, applies the dwell (a camera must be clearly better for `dwellSeconds`), then calls `stage.cut(toSlot:fade:)`. With 2+ cameras the director owns which is live, so `CutoutPublisher` never stands in a default camera. Coordinator starts it at ~369/394 and resets to slot 0 (`cut(toSlot: 0, fade: 0)`) at session start/stop.

**Presence bubble.** The on-screen camera bubble (App/UI/PresenceBubble.swift, wiring in `CoordinatorController+Presence.swift`) moves the camera in the picture: drag -> `PresenceGeometry` -> `stage.updatePlacement(layout)` per step (no camera reopen), final -> `applyPresencePlacement`. It shows the processed camera via `stage.setSelfViewHandler`, never mirrored (called on the render queue; must return quickly). **Two capture paths, kept apart.** (1) Greenroom's own capture: `StageScreenSource` excludes the whole app via `SCContentFilter` and lets back in only `ShareVisibleWindows`; the bubble is never registered there, and the compositor draws the camera itself, so the class picture has it exactly once whatever the next point says. (2) Other apps (QuickTime, Loom, OBS, a native Zoom share) ignore our filter and read each window's `sharingType`: `sharingType` is `.readOnly` for the bubble panel and every other Greenroom window (decision 2026-11-25: no switch; the Room screen and setup guide included), except `.none` for the bubble in Only me (`PresenceRecorderRules.cameraBubbleSharing`, live through `RecorderVisibility.cameraState`). Greenroom's own picture excludes every Greenroom window by the app-wide filter, whatever sharingType says. "Mirror my camera" (camera look, `PresenceFeed.mirrorKey`, default on) flips ONLY this bubble on the owner's screen (`CameraLookRules.mirrorsBubble`; `stageMirrors` and `recordingsMirror` are false: the meeting's picture, Greenroom's recordings and the Room screen never flip); other apps' recordings may show the flipped bubble, accepted 2026-11-25. It feeds at its real pixel size (frame x backingScaleFactor, capped at 1920) and shows its outline/handles only while grabbed (+0.5 s fade). `PresenceVisibility.decide` says whether to show it given share kind, meeting state, captured window.

**Other readers of the compositor.** Recording border and input mapping: `capturedScreenFrame`, `capturedWindowID`, `capturedFrontTarget`, `followsWindow`, `videoPosition(ofGlobalPoint:)` (App/Recording/InputEventTracker, ScreenAnnotation, DebugTour). Recorder audio: `onSystemAudio`. Whiteboard: `setWhiteboardPage` (CoordinatorController `pushWhiteboardPage`) and `StageInputBoard.setWhiteboard(mode:)`. Marks: `setMarksOverlay(StageMarksOverlay?)`.

## To change X, go to Y

- Change the picture's size or fps -> `StageCompositor.init(size:frameRate:)` (default 1920x1080 @ 30); downstream consumers adapt (`I420Converter` for the meeting).
- Change how the camera bubble/cutout/presenter is drawn -> `StageRenderer.compose` / `pixels(of:scene:)`; shape masks live in `WebcamShape` plus the renderer's `masks`; defaults in `StageLayout`.
- Add a new webcam shape -> `WebcamShape` (case, `label`, `usesChromaKey`), then the renderer's mask code and the Layouts camera inspector (`ShapeGlyph` went with the Webcam tab).
- Add a share kind -> `ShareTarget.Kind` (+ `capturesScreen`, `resolve`), `StageScreenSource.Target`, `StageCompositor.syncScreen`, `StageConfiguration.normalizedLayout`.
- Change which windows can be picked -> `ScreenWindowRules.isCandidate/placement`, `ShareTarget.windows()`; how an app is matched -> `ScreenAppMatch.match`.
- Change slide-show follow -> `SlideShowFollow.decide` (pure) and `StageScreenSource` follow loop (~line 507).
- Change what Greenroom hides from / shows in a display share -> `StageScreenSource` filter (~line 259) and `ShareVisibleWindows`; the "Show on my share" rule is `ShowOnShare` in App/ShareVisibilityRules.swift. The Greenroom Browser has no eye switch and is always let in (`ShareVisibilityRules.alwaysShared`, fed by `BrowserWindowController.visibleWindowNumber` via `ShareVisibleWindows`).
- Change screen-capture retry/backoff -> `ScreenRecovery.retryInterval` / `failed`, `StageCompositor.syncScreen`, `kickScreen`.
- Handle a display plug/unplug differently -> `StageCompositor.displaysDidChange` and `apply`; the plan -> `DisplayPlan` (codemap/layout.md).
- Change blur or image backgrounds -> `CameraEffects.apply`, `MaskRefiner`, `CameraBackgroundLibrary`, presets in `App/Stage/Backgrounds/` and `CameraBackgroundPreset`.
- Change segmentation quality or camera open/recovery -> `CutoutPublisher` (Vision request, `recover`, stand-in rules).
- Tune auto camera switching -> `CameraDirectorSettings` defaults, `Chooser` (decision), `CameraDirector.score(yaw:pitch:)`, `CameraTransition`.
- Fix the aim-a-camera readout -> `CameraProbe` (it must stay independent of the compositor).
- Add a new consumer of frames -> implement `StageFrameSink`, `stage.addSink`, keep a strong reference; follow the rules in `StageFrames.swift`.
- Change preview refresh rate/size -> `StagePreviewSink` (rate rule: `PreviewRate` in App/UI/PreviewFrameRules.swift; `meetingLive` is set by the coordinator). Measure with `log stream --predicate 'category == "preview-fps"'` (Debug).
- Change presence-bubble maths (clamp, size steps) -> `PresenceGeometry`; when it shows -> `PresenceVisibility.decide`.
- List attached cameras/mics/displays by stored ID -> `LocalDeviceResolver`.
- Change the no-picture card -> `AudioOnlyCard.image(size:)`.

## Gotchas

- **Never draw on the main thread, never block `renderQueue`.** Everything render-side runs on `greenroom.stage.render`. `StageStatus` is mutated on the main thread only (via `post`). `StageRenderer.lastContentRect` / `lastCameraCoverage` are lock-protected and read from any thread; they describe the frame most recently drawn.
- **Locks, not actors.** `StageCompositor` control state is under `lock`, inputs under the board's lock, handlers under `LockedBox`. `CutoutPublisher.removesBackground` / background are lock-guarded (written on main/control, read on the capture queue). Do not read control state from `tick`.
- **Live changes must not blank the picture.** New screen capture starts beside the old and replaces it on first frame; a lost capture keeps the last frame (still image, not black); camera changes never reopen cameras (`updatePlacement` skips `apply`).
- **Stale async rounds.** Anything async after `apply` must check `isCurrent(generation)`; `Task.detached` retries re-check it.
- **Frame contract.** Frames are BGRA, IOSurface-backed, host-clock timestamps; `StageFrameSource` holds sinks weakly. Do not change the pixel format without updating `ZoomVideoSender`/`I420Converter` and the recorder.
- **Windows are remembered by app + title, never window ID** (`ShareTarget.windowKey`). A saved `.app` kind is read back as the whole screen (`pickable` omits it but it must still decode).
- **Own windows are excluded from display shares** (feedback loop) except those in `ShareVisibleWindows`; the window number equals `NSWindow.windowNumber`.
- **Screen Recording permission.** `StageCompositor.screenRecordingGranted` does not prompt; `requestScreenRecordingAccess` prompts once, then opens System Settings once per launch. Without permission other apps' window titles are empty and `ScreenRecovery` does not retry.
- **Sleep/lock and -3815** end the SCStream; recovery logs once per outage ("a night of sleep is a counter, not 600 lines").
- **One camera opener.** CameraDirector reads the compositor's own sessions (`latestCameraFrame`); never open a second AVCaptureSession on the same device. `CameraProbe` is for when nothing is running, and the compositor stops it once the director owns cameras (`cameraProbe.stop()` in `runPipeline`).
- **Idle preview runs the director.** With switching on and 2+ cameras chosen, the Settings/Home preview opens every chosen camera in the stage (`makeStageConfiguration` with `stageCameraUIDs == nil` and no session) and `CoordinatorController.syncIdleDirector` runs the director on it, so the preview cuts like a class. `buildScene` and `stopStage` stop it; a session brings its own cameras in. Aim then uses `startExternal` (the director's `slotSights`), never a second opener.
- **Director vs stand-in.** `setAllowsStandIn` is true only with one camera; with several, the director chooses.
- **Xcode 27 SDK:** `CGDisplayCreateUUIDFromDisplayID` moved to ColorSync; `LocalDeviceResolver` imports it by name (see header comment). Keep that import.
- **Colours are DESIGN.md neutrals** (`--ink` #101828 backdrop in `StageRenderer`, `AudioOnlyCard`); no hardcoded greens.
- **Recorditor ports** (`CameraEffects`, `SlideShowFollow`, whiteboard, `AudioOnlyCard`) have a diff log in `docs/recorditor-integration/` (camera-port-log.md, follow-port-log.md); keep it current when changing them.
- **Tests that pin this area** (Tests/): `PresenceRecorderRulesTests`, `PresenceGeometryTests` (also `PreviewFrameRulesTests`), `PresenceVisibilityTests`, `SlideShowFollowTests`, `ScreenRecoveryTests`; `ScreenAnnotationTests` touches `AudioOnlyCard`; `HomeCalmRulesTests` touches `ShareTarget`. Not covered: `StageCompositor`, `StageRenderer`, `CutoutPublisher`, `CameraDirector`, `ScreenAppMatch`, `ScreenWindowRules`, `LocalDeviceResolver`.

## Who sees what (one rule)

`ShareVisibleWindows.effectiveNumbers` (the list `StageScreenSource` passes to `SCContentFilter` as exceptions) is built by `ShowOnShare.exceptionIDs`, which asks `Visibility.windowBadge` (App/Layout/Visibility.swift) whether a marked window and the always-shared Greenroom Browser are in a whole-display share. The Browser's window number is passed unconditionally; the rule decides. `Visibility.Target(ShareTarget)` (in `ShareVisibleWindows.swift`) maps what is shared to the rule's targets. DEBUG: `ShareVisibleWindows.crossCheck(pieces:target:)` logs and asserts when a fixed answer of the rule disagrees with the live list. `CameraState` (App/Stage) is the four-way camera state (Everyone and me / Only everyone / Only me / Off), the pair `noCamera` + `cameraShownOnMyScreen` read as one word (`init(noCamera:shownOnMyScreen:)`, `.noCamera`, `.shownOnMyScreen`, `migrated(...)` for old defaults, `raw`/`name`/`detail`/`symbol`). `CameraStateSession` = saved default + the running meeting's live change (`setLive` never writes `saved`; `resetToDefault` at Start/Snap Back). `MeetingSetup` holds it (its only holder; saved per layout since meeting-setup P2): the coordinator's `cameraState` (in use), `savedCameraState`, `setSavedCameraState` (Settings -> Layouts), `setLiveCameraState` (bar and Home: saved before a meeting, for this meeting during one) and `applySetupEvent` (drops the for-this-meeting change at start, Snap Back, meeting end and a layout switch, except a camera turned Off, which survives a switch, R5.4). The two old keys are import-only except with no layout active. The whole matrix (every surface x the four states, plus the transitions) is `Tests/CameraMatrixTests.swift`. `cameraIsOff` reads the current state's `noCamera` (not in everyone's picture). "Only me" is a true mirror (P8): `Visibility.cameraMirrorOnly` / `cameraRuns` decide, `StageLayout.mirrorsCamera` keeps the camera open (`opensCamera`, read by `StageCompositor.apply`, `sceneCameraUIDs`, `isPresencePlaceable`) while `showsCamera` stays false, so `StageRenderer.compose` leaves it out of everyone's picture; only Off closes the camera.
