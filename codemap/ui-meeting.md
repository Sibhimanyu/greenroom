# codemap: App/UI meeting windows (MeetingVideo, ParticipantConsole, meeting window, toolbar, menus)

Greenroom's own meeting UI (Zoom runs in custom-UI mode, the only mode: the SDK owns no windows). Two surfaces: (1) the single Meeting window (`ParticipantGridWindowController`, one 3.4k-line file; the old full-display "reference" rail panel was removed 2026-11-24) with a Zoom-style dark look, top bar, video stage, one side panel (chat or people) and a foot toolbar; (2) separate "view windows" (`MeetingViewWindows`, one per `MeetingView`: Active speaker, Gallery, Multi-speaker, Speaker + strip, Self view, People list, Shared screen, Spotlight person, Hands up) that a layout can place individually. The participant "console" pieces (Cues container in the Live Queue view, inspector drawer, self preview, people panel) feed the Meeting window's People panel. Main-app screens are in `ui.md`.

## How it fits
- Hosting: `ParticipantGridWindowController.refresh` makes/updates one `MeetingControlPanel` (non-activating `NSPanel`, titled, never borderless) holding `MeetingRootView`. `Form` decides the look: The full-display `.reference` rail panel (header, rail with self block and button cluster, Live Queue, context bar, "Waiting for people...") is gone (2026-11-24); a Meeting piece that fills a display opens `.placed(screen.visibleFrame)`. `.meeting` = free window (may fill a teacher-only display the first time); `.placed(frame)` = layout slot, compact (<760x520, `LayoutResolver.isCompactMeeting`) = Speaker view with chrome on hover. A change of form kind = a new window.
- `MeetingRootView.setupMeetingForm` (meeting forms) builds `meetingTopBar`, stage, share, side panel (`peopleView` or embedded chat `chatHost`), and the foot toolbar host (`FirstMouseHostingView(rootView: MeetingToolbarView(model: controls, coordinator:))`). Layout in `layoutMeeting`, `layoutSidePanel`, `layoutFilmstrip`, `layoutMultiSpeaker`; view mode `ViewMode`=`MeetingViewMode` (Speaker/Gallery/Multi-speaker), share layouts `MeetingShareLayout`; roster in via `update(roster:...)`, rows via `applyPeople`.
- Which surface shows: `MeetingSurfaceOwner.model` (a `MeetingSurface`). Everything that changes it sends an event: `CoordinatorController` (`start` -> `.startBegan`, go-live -> `MeetingSurface.wentLive(layoutPlacesMeeting:)` (`.wentLiveOnBar` unless the layout places a Meeting piece, R48), `openMeetingWindow`/`closeMeetingWindow`/`move`/`toggleSpeakerTile`/`placeCustomSurfaces`/close sheet answers/`bringLiveSessionForward`, `stop`/`chatSessionDidEnd` -> `.sessionEnded`), the Bar's window observers (`syncWindowFacts`, which turns what the window reports into covered/minimised/other-desktop events), and the morph's end (`.morphFinished`). `MeetingControlBarController.render()` draws the Bar from `surface` (not during a settle or a morph); the window is shown/hidden by the actions that send the events. A once-a-second safety check in the bar controller (`safetyCheck`, started at `install`, stopped at `close`) compares `windowIsOnScreen` and the bar's visibility with `screenMatches` and corrects, logging in DEBUG (Logger category `meeting-surface`). Reopen (Dock, menu) reads `model.reopenTarget`: the window unless the person chose the bar.
- Controls state: coordinator owns one `MeetingControlsModel` (set as `ParticipantGridWindowController.controls`). The same model drives the foot toolbar (`MeetingToolbarView` -> `MeetingToolbarBar`) and the floating pill (`MeetingControlBarController.install`, shown only when no meeting window carries controls). Pill collapses to a 44pt puck; placement rules App/MeetingBarPlacement.swift; shrink/collapse morphs App/MeetingMorph.swift, App/MeetingShrinkRules.swift, App/MeetingCollapseRules.swift.
- Menus: `MeetingMenus` builds `[MenuEntry]`; `MeetingMenuBuilder.popUp` -> `MeetingMenuPanel` (toolbar, top bar View button); puck, tile right-clicks, view-window picker and People "..." too; NSMenu is not used in those windows. `MenuBarStatusItem` turns the same list into an NSMenu submenu for the menu bar (a status-item menu is tracked by the system, so it works while inactive).
- View windows: `MeetingViewWindows.configure(client:log:frameFor:copyInvite:openMeetingWindow:keepFollowing:)` is called by CoordinatorController; opening a view calls `keepFollowing`, which restarts the coordinator's one-second follow loop if closing the Meeting window had stopped it (otherwise the view drew once and never updated); the layout runtime opens each view piece at its frame; windows open 0.5 s apart; each owns a `WindowShareController` (eye, off per launch).
- Readiness: before connect, `ReadinessHUDController` hands the start steps (`NotchStep`) to the island (NotchStatusController); the Meeting window has no readiness card.
- `PeoplePopOutController` is the Participants panel in its own window; folds into the window's People panel when the Meeting window is back in view (like chat pop-out).
- Every bar-opened window (views, Meeting window, Chat, People) goes through `NSWindow.comeToThisDesktop(settledBehavior:)` (MeetingViewWindow.swift), new windows too, so it lands on the desktop in view, a full-screen one included. Chat and People are `KeyablePanel`s (`.nonactivatingPanel` from init, `canBecomeKey` true): a plain NSWindow of an inactive app cannot join a full-screen desktop.

## Gotchas

- Zoom-familiar dark look is a recorded owner decision (DESIGN.md, 2026-11-12) overriding "do not imitate Zoom" for this window only: dark aqua forced, fixed `MeetingTheme` values, SF Symbols only, never Zoom's logo/word as branding. The Zoom-ish greens here are NOT `Brand.green`; the app accent stays untouched elsewhere.
- Meeting windows are real titled windows, never borderless (close button + title bar always). Panels are non-activating (`MeetingControlPanel`, `MeetingViewPanel`, Control bar `BarPanel` never key/main): a click must not pull Greenroom forward over the teacher's slides. `MeetingViewPanel.keyable` only for People list (search).
- Control bar/floating pill: a floating surface, so glass rules apply; anything new on it follows `MeetingBarModel` rules (owner 2026-11-13): non-universal icons carry a word, one timer in the REC pill, End is the only red control, rare actions fold into REC menu / More.
- Toolbar: Mute is never dropped, More is always present (holds Meeting info, Open in Zoom app); Security only for host/co-host; drop order is the `keep` numbers, clock goes before action controls. Never let it squeeze: fit is arithmetic, tested in Tests/MeetingToolbarTests.swift. Home's toolbar chevron rule is separate (`HomeToolbarRules`, see ui.md).
- Video views: an SDK video view has one superview. Speaker stage is not a tile (`stageHost`); render order matters (show panel, lay out, create elements, subscribe once visible). View windows that are minimised or ordered out for >= 3 s release their elements (occlusion and other Spaces do NOT count: that flapped and showed frozen video); a speaker change keeps the element and sets a new `userid`; black-window fallback after 6 s offers "Use the meeting window" (`meetingWindowOnly`).
- Participant console views are fixed pools written in place, never rebuilt per poll (tearing views down races the accessibility tree); Live Queue width is fixed (320) so Cues arriving cannot move the layout. The inspector and side panel overlay the grid below `MeetingRootView.narrowWidth` (900).
- Everything in App/UI/MeetingWindow/ is pure AppKit (frames, no Auto Layout in most paths): `layoutEverything` / `layoutMeeting` own geometry and apply the rectangles `MeetingWindowLayout` computes; do not set frames elsewhere. A new sum goes in the rules file with a test, not in the view.
- UI words: "meeting", not "class" (a few old comments/ids say class; no new user text with it). Greenroom windows are out of screen capture unless the eye adds them (`ShareVisibleWindows`).
- Raw values of `MeetingView` and `MeetingViewMode` persist (saved layouts, UserDefaults): never rename.
- Debug-only: `PeoplePopOutController.debugRowCount` and `MeetingPeopleView` debug hook (line ~295) stay under `#if DEBUG`.
- Notes bar (`App/UI/SessionNotesBar.swift`, `SessionNotes`): a floating Liquid Glass (`.greenroomGlass`) non-activating panel for the session. Dragged by its background (`NotesBarDragSurface`, an AppKit view under the field; `isMovableByWindowBackground` does not work on the hosting view); `SessionNotes.dropped` clamps it and saves the spot per display (UserDefaults `sessionNotesBarSpots`, display UUID -> offset from the visible area, pure rules `NotesBarPlacement` in App/MeetingBarPlacement.swift), restored on each show on the display it was last dropped on (`sessionNotesBarLastDisplay`, `NotesBarPlacement.restingDisplay`: that display when connected, else the main one). Never content: whole-app exclusion keeps it out of Greenroom's own capture. Esc (empty field) and the x close it.
