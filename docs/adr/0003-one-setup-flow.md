# One module decides the Zoom setup step; pages are read into data, and the step comes from evidence

The guided Zoom setup now has one deep module, `ZoomSetupFlow`, which turns facts into the current step and its single call to action. The guide, the Greenroom bar and the coach only render that step. Zoom's page is read by one script into a plain `ZoomPageSnapshot`, behind a `ZoomPage` seam with two adapters (the real WKWebView, and recorded fixtures). `ZoomActor` runs "Do this step" plans against the same seam. The step is the first one in a fixed table whose evidence is missing. Evidence comes from pages seen and from the check, so in-page menus, dialogs and Zoom's own tab order no longer derail it.

We chose this over continuing to patch the previous design: about twelve rule files and six page scripts, each deciding the step from the current address. The owner saw them disagree (the guide said "Needs a fix" while the bar said "set up"), saw cards with no action, and saw steps that never advanced. It had grown to about 4,300 lines with no test that ran the whole flow. The cost is a rewrite of the setup's insides and a fixture recorder. In return, one table answers "what now?", every surface shows the same answer, and the whole flow is tested by replaying real recorded pages in `scripts/check.sh`.
