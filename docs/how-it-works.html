Privacy & safety

Is Greenroom watching your screen? No.

Here is every process, permission and network call it makes — drawn, not asserted. No server of its own, and no cloud AI: the one model it can run is Apple's, on this Mac, and only if you turn Prompter on. Two things leave without you asking, and both have a switch: usage analytics (counts and timings, never names or meeting IDs) and, while the built-in browser's search suggestions are on, what you type in its address bar. Class content leaves only if you turn on YouTube upload, and then only your own recording; with Prompter on, the short search phrases it builds leave too, and each one is written to the log. Follow the diagrams and you've audited the app.

04 · Permissions

What macOS grants vs. what the app uses

You approve each of these yourself and can revoke any of them in System Settings → Privacy & Security. Greenroom can't grant itself anything.

Camera one of the two entitlements
live meeting videounused

Zoom's Meeting SDK runs inside Greenroom, so the camera is opened in its process — that's exactly why it holds this. Used for the meeting only: your composited picture, read from the OBS Virtual Camera, on its way to Zoom.

Microphone the other entitlement
meeting audio · level meter · Prompter (opt-in)unused

Three readers of the same device, all inside a class and none outside one: Zoom's SDK sends your voice to the meeting; the participants panel's level meter shows whether it hears you; and, only with Prompter turned on, Apple's speech model turns it into text on this Mac. Prompter reads the default input device — never Zoom's incoming audio — pauses while you are muted in Zoom, keeps the text in memory only, and drops it when the class ends. macOS asks no additional permission for that: it is the same microphone grant, and no speech-recognition service is involved.

Accessibility system-wide window control
4 reads · 3 writeseverything else unused

Broad by design — macOS has no narrower option. The honest safeguard is the code: it only ever touches the window values in the diagram above, on named windows. Verifiable in AppWindowManager.swift. Not used at all for the main pane when Greenroom Browser is the main app.

Automation Apple Events
open + size a browser windowunused

External Chromium-family browsers only (Chrome, Edge, Brave, Ulaa…), and macOS asks per-app the first time. Greenroom Browser needs no Automation permission.

Screen Recording belongs to OBS
not requestedGreenroom contains no screen-capture code

OBS holds this permission and does the capture. Greenroom only hands it the identifier of the display to show.

Global shortcuts Carbon RegisterEventHotKey
8 fixed combosno key monitoring · no event taps

⌥⌘ + G / X / R / S / Z / 1 / 2 / 5. macOS reports only that one of those eight was pressed — it cannot see anything else you type. Control is deliberately not in the combination: Control-Option is VoiceOver's own modifier, so those presses are swallowed whenever VoiceOver is running.

05 · Every network call

Eight channels. That's the whole list.

Four are Greenroom's own. Two exist only when you choose Greenroom Browser as the main app, and one of those has its own switch. The seventh carries class content — your recording — and the eighth carries the search phrases Prompter builds from what you say. Both are off until you turn them on.

Leaves your Mac

api.zoom.us · zoom.us

Your meeting audio, video and chat, and requests to create or join your own meetings — through Zoom's official software. Identical to using Zoom directly. Before creating a meeting it also lists the account's live and scheduled meetings, and ends a meeting left live from a crashed or force-quit session — Zoom allows a host one live meeting, so a leftover would make the new class fail to start. It says so in the status log whenever it does this.

Leaves your Mac

github.com · sibhimanyu.github.io

A periodic update check and the download if you accept one. EdDSA-signed, verified against a key inside the app, so only genuine releases install.

Leaves your Mac

Zoho Apptics

Anonymous usage analytics: which features get used, which settings are switched on or off, roughly how long a session ran, whether something failed. Counts, coarse durations and enum codes only — never student names, meeting IDs, file paths, web addresses or chat, because the status log those events are derived from is deliberately never forwarded. The chosen main app is reported as one of four kinds, never by name. Settings → Layout → Privacy turns it off, which stops every call including registering this Mac.

Leaves your Mac · Greenroom Browser only

the pages you open

Only when Greenroom Browser is your main app. It is Apple's WebKit — the engine inside Safari — running in Greenroom's process, so the sites you visit load from Greenroom instead of from Chrome, and see the same request any browser would send. Cookies and sign-ins stay in WebKit's standard store under ~/Library; the visited-pages list is one local file, ~/Library/Application Support/Greenroom/browser-history.json, with a Clear History button. Nothing about your browsing is sent anywhere else.

Leaves your Mac · optional

suggestqueries.google.com

While Settings → Layout → Suggest searches as you type is on, each keystroke in the address bar is sent to Google for completions — exactly what Chrome and Safari do. Switch it off and only your own history is suggested; nothing leaves until you press Return.

Leaves your Mac · off by default

youtube.googleapis.com · oauth2.googleapis.com

The one channel that carries class content: when Settings → YouTube is set to ask or to upload automatically, a finished recording — the shared screen with you in it, and your voice — is uploaded over HTTPS to the connected Google account's channel, unlisted or private as you chose. Sign-in happens in your browser on Google's own page; Greenroom keeps a token that can upload and edit the account's own videos (it uses it for uploads and title changes, nothing else), revoked at Google by Disconnect. With “Do nothing” selected (the default) this channel does not exist.

Leaves your Mac · off by default

en.wikipedia.org · googleapis.com/books · openlibrary.org · youtube · a named product’s own site

Only with Settings → Prompter on. When you name a book, a video, a topic, a person or a place, the short search phrase Prompter built — a title or a name, deterministic, a few words — goes over HTTPS to Google Books then Open Library (books), to Wikipedia's title search (topics, people, places), and, if you allow it and a Google account is connected, to the YouTube Data API (videos; otherwise the card is a search link that sends nothing until you open it). One more, added after watching a real class: when you name a product, Prompter guesses its address from the name (“Haiku Deck” → haikudeck.com), opens that page and reads its title to check the site is really there. It reads only as far as the title and offers the card only if the title matches the name. That is a request to that product’s own site, the same page you would open yourself — never a search engine, and nothing is scraped. Never the audio, never the transcript, never anyone in the meeting: a phrase matching a roster name is dropped before any request. Each phrase sent is written to the status log and to ~/Library/Logs/Greenroom-session.log, with the host it went to. Card thumbnails are fetched from the same hosts. Capped at 30 lookups a class; a fixed User-Agent names Greenroom.

Stays local

ws://127.0.0.1:4455

Authenticated loopback socket to OBS. Never touches the network. Recordings are written to a folder per session under ~/Documents/Greenroom, with any clips you mark beside them.

This socket is also how a clip is saved after the fact — see the clip buffer below for the full machinery.

09 · Full honesty

The weak spots

Zoom and YouTube credentials are stored in plain text on your Mac

The Zoom app credentials you enter, and the YouTube sign-in token if you connect a Google account, are saved in Greenroom's local preferences as plain text — not encrypted. Greenroom doesn't use the macOS Keychain at all. They never leave your Mac except to Zoom and Google respectively. The risk is purely local: anyone with access to your Mac user account could read them. The YouTube token can upload and edit the account's own videos (Greenroom uses it for uploads and title changes only), and Disconnect revokes it at Google.

In perspective: these are app-level Zoom API keys scoped to running meetings under your account — not your Zoom password — and revocable anytime in the Zoom Marketplace. The optional "export settings" file used to set up a colleague's Mac also contains them in plaintext by design; hand it over directly and delete it after importing.

With Prompter on, the search phrases say what your class was about

Prompter sends only the phrase it built — never audio, never the transcript, never a name from the meeting — but a term's worth of phrases to Google Books, Wikipedia and YouTube is still a record of what you taught, seen by those services like any search you typed yourself. Greenroom adds nothing to identify you beyond the connection itself (and, for YouTube video search, your own connected account). It is off by default; it pauses while you are muted; the menu bar can stop it for a class; and the log names every phrase, so you can see exactly what left.

Two more limits, plainly: it hears your microphone, so a student's voice coming out of your speakers can reach it as room sound (a headset removes that); and the word-pattern fallback, used when Apple Intelligence is off, finds fewer things than the model does.
